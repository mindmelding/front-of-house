# Legends

At Eleven Madison Park, Will Guidara's team kept a running record of the gestures that landed: the hot dog for the table that hadn't tried one, the sled trip for the family whose beach week got snowed out. They called them legends. The point was never to repeat the gesture. It was to teach the move behind it, so the next person could find their own.

This folder is that record. One file per legend, dated, anonymized, short.

## Template

```markdown
---
id: legend-YYYY-MM-DD-slug
type: legend
status: active
last_reviewed: YYYY-MM-DD
trigger: <one of the catalog triggers>
---

# <Title: the move in five words>

**Date.** YYYY-MM-DD
**Trigger.** What signal in the file started it.
**What we noticed.** The specific detail, and where it came from.
**What we did.** The gesture, verbatim if it was a message.
**What happened.** Their response, or what changed.
**The move to reuse.** One sentence a stranger could apply to a different customer.
```

## Rules

1. Anonymize. Synthetic names, no company identifiers, no dollar amounts that would identify a contract.
2. Only gestures that landed. A gesture that fell flat goes in `inbox/` under Missed, not here.
3. The last line is the point. If you can't state the reusable move, it isn't a legend yet.

## Why these are public

Legends double as the public feed. Alongside `CHANGELOG.md`, they are a weekly "what we learned about hospitality" publication that costs no extra writing.
